## フェーズ構成

### Phase C｜静的サイトで世界観・設計を確定
MakeShopに依存しない形で、ブランドの見た目とページ設計を完成させる。

- 成果物
  - `data/products.json` … 企画書§6の45商品を構造化した唯一のデータソース
  - `site/` … 静的HTML+CSS（TOP／カテゴリ一覧×5／商品詳細×45／ABOUT／GIFT GUIDE／NEWS・FAQスタブ）
  - `site/build.mjs` … products.jsonからページを生成する小さなNodeスクリプト（フレームワーク不使用）
  - プレースホルダ画像システム（カテゴリ色×幾何学図形のSVG、文字描き込みなし）
- 技術方針
  - 素のHTML＋単一CSS（カスタムプロパティでトークン管理）。MakeShopテンプレートへの移植コストを最小化するため、ビルド依存を持たない
  - JSは最小限（SPメニュー、タグ絞り込み、カートボタンのデモ挙動のみ）
- **完了ゲート（fact-checkで機械検査）**
  - [ ] 45商品すべてにページが生成され、SKU・商品名・価格が企画書と100%一致
  - [ ] 内部リンク切れ 0
  - [ ] PC（1280px）・SP（375px）で全ページ表示確認
  - [ ] 全ページにポートフォリオ注記（企画書§10）表示

## モデル・エージェント運用（CLAUDE.md準拠）

- 設計確定（本ドキュメント＋design-spec.md）までが **Fable**。以降の実装は **Opus に戻す**
- 委譲ルール
  - builder（sonnet）: products.json転記、ページ量産、CSV生成
  - fact-check（haiku）: 価格・SKU突合、リンク検査、件数検査
  - researcher（sonnet）: MakeShop公式マニュアル調査（結論の採否はメイン）
  - critic（opus）: 各フェーズ完了ゲート前の敵対的レビュー
- 新たな路線判断（例: トライアルの制約で設計変更が必要になった場合）が発生したら、再度 /model fable を提案する

## 不変条件（全フェーズ共通）

1. SKU・商品名・価格・カテゴリ・仕様・カラー・説明文を変更しない（企画書§1）
2. 架空ブランドである注記を全成果物に含める（企画書§10）
3. MakeShopの仕様を推測で断定しない。未確認は「要確認」と明記（企画書§1・§8）
4. 画像内に文字・ロゴを描き込まない。文字はHTML側で組む（企画書§1・§7）
